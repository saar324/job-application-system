# Sequential applications

One main chat controls the internal browser and one application at a time. Exactly two search-only agents replenish the passive queue using exclusive ranked source leases. Read [search-workers.md](search-workers.md). No parallel form workers or server background campaigns.

- Append owner links as they arrive. Server state determines queue order and deduplication.
- Finish the current application before claiming the next. The main chat processes queued jobs while the search agents discover more.
- Search workers follow configured source priority while search remains authorized. Daily Europe/Sofia resets reopen priority and keep handled-job history. Preserve source cursors and shared request budgets. Stop on challenges and access restrictions.
- Check saved facts, prior answers and owner corrections once, then reuse still-current evidence. Draft grounded prose when permitted. Review the actual complete form and submit under the owner's routine delegation.
- For missing facts, CAPTCHA, uncovered commitments or tool permission, checkpoint the current application, leave Chrome visible, ask the owner and wait. Record new links while waiting, but do not advance the queue.
- A final action has one durable attempt. Timeouts, restarts and unknown results do not permit another Submit. Reconcile the outcome first.
- Close the session-owned application tab after a verified receipt or explicit skip. Keep user-owned tabs untouched.
- Count only real employer receipts. Historical applications and simulations are separate from the current request.

The queue is the working ledger. Existing application logs, recruiter records, source configuration and old batch audit files remain historical evidence; do not restart an old campaign or reconstruct live work from an abandoned browser tab.

## Buffered preparation

Use the 20/30 search-control cycle and one draft packet per job. Load and correct the packet before entering answers, then batch deterministic matching fields in the Codex internal browser. Custom dropdown selections, actual CV/letter uploads and post-fill verification still require browser observation. A packet does not prove live insertion or submission. Read application-drafts.md.
