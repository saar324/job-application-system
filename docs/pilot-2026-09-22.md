## Measurements

- Bounded Himalayas search: 287 listing results, 33 passed source-level qualification, and 254 were excluded. The official configured-source scan returned 208 listing results, with nine passing source-level qualification. These counts may overlap and are not counts of distinct eligible jobs.
- ElevenLabs was queued at 11:35:09 UTC and produced an initial preview at about 11:37:26 UTC, roughly 2 minutes 17 seconds later. Visual inspection found that preview incomplete, so it is not counted as ready. The first six questions required fact checking or writing; browser execution took only seconds.
- Aggregate server metrics after the tenth role: queue median 478 ms (20 samples); execution median 2.6 s, p95 26.2 s (32 attempts); worker active median 3.4 s, p95 25.7 s (17 samples). These are cumulative metrics, not an isolated ten-application sample. The attempt count includes retries during fault repair.
- Model and coordinator token counters are unavailable (`null`). We cannot claim token savings from this pilot.
- The user's former estimate of 100 applications in eight hours is a reference point, not a verified baseline. With zero submissions, there is no defensible post-upgrade throughput comparison yet. Current blockers are candidate supply, required owner facts, challenges, and review, while browser execution itself measures seconds on most attempts.

## Defects found and fixed

The live Xebia form exposed two worker defects. A public reCAPTCHA iframe was treated as a forbidden top-level destination, and a passive invisible reCAPTCHA badge was treated as an active human challenge before safe form fields were filled. The worker now checks the application-host allowlist for top-level navigations, still validates public DNS on every request, fills safe controls before challenge detection, and pauses only for an interactive challenge. Regression tests cover both cases. Commit `269758f` was deployed to the production worker. The full check passed: 156 tests and the repository privacy gate.

The ElevenLabs form exposed a third defect: Ashby's required custom controls lack native `required` attributes. The worker's initial final preview omitted them. A provider-specific audit now blocks approval until those controls have been inspected, and a refresh operation superseded the stale preview without approving or submitting it. The worker can select and verify these controls from exact answers, and includes them in the preview. Location and referral source have been recorded; the degree and immediate full-time availability question awaits the owner. This version is deployed to the production API and worker. The full check passed: 159 tests and the repository privacy gate.

Fresh web search during the pilot found several good matches, but their exact employer role IDs already had submitted or rejected records. The manual log check is now a deterministic production search filter: it removes profile-specific handled Ashby, Greenhouse, and Lever roles before board result limits, and removes handled results from all source responses before scoring. A live Ashby query for a previously handled Kestra role returned one handled result filtered and no candidate items. Closed search-index results also consumed attempts before live board verification was made part of the search step.

## Next bottlenecks

1. **Candidate supply and eligibility.** The new search filter removes roles already in the application history. Board searches can still return stale or geographically ineligible roles, so verify the official employer posting and Bulgaria eligibility before preparing a form.
2. **Known-answer reuse.** The ElevenLabs worker requested GitHub and LinkedIn links already present in the saved profile. Composite labels such as “Link to your Github or profile” need safe deterministic mappings. Reuse employer-scoped and previously confirmed prose carefully; do not treat unreviewed historical drafts as owner facts.
3. **Custom form scoping.** Intetics presents multiple forms on one page. A provider adapter or stronger application-form selection could identify the correct controls; the CAPTCHA remains a human step.
4. **Coordinator telemetry.** Time spent finding, deduplicating, verifying, and writing applications is not measured by `application-metrics`. Add stage timing and token counts before claiming end-to-end speed gains.
5. **Relevant optional questions.** Dash0 reached final review with AI experience and startup experience blank. The worker should use verified evidence for relevant optional answers and include their final values in approval review.
6. **Direct-link metadata.** Directly queued Ashby and Lever forms are recorded as `Direct application` at `jobs.ashbyhq.com` or `jobs.lever.co`; the application record should inherit verified employer and role metadata.

Continue only with verified, eligible, unapplied roles. Exact completed previews need owner approval before submission. Unknown legal or personal facts require owner answers, and CAPTCHAs require human action.
